### 1.2 存在问题

#### 问题一：登录机制与设计不符

- **设计要求**：无正式登录，仅通过 `userId` 区分用户，首次使用时生成，持久化到 `localStorage`
- **当前实现**：`user.ts` 实现了 `username/password` 登录，调用 `POST /auth/login`（该接口在后端 API 文档中不存在）
- **解决方案**：重写为 `userId` 机制，首次访问生成 UUID 存入 localStorage

#### 问题二：聊天 Store 接口调用错误

- **当前调用**：`GET /chat/conversations`、`POST /chat/send`
- **实际接口**：`GET /api/sessions?userId=...&page=0&size=20`、`POST /api/chat/stream`
- **解决方案**：重写 `chat.ts`，对齐 API 文档中的全部 6 组接口

#### 问题三：缺少 x-markdown-vue 依赖

- **设计要求**：使用 `XMarkdown` 渲染 AI 回复内容（支持 Markdown + 代码高亮）
- **现状**：`vue-element-plus-x@2.0.3` 已将 XMarkdown 拆分为独立包 `x-markdown-vue`
- **解决方案**：安装 `x-markdown-vue` 包

#### 问题四：组件名称纠正

- 设计文档中提到的 `EditorSender` 在 `vue-element-plus-x@2.0.3` 中实际名为 **`XSender`**
- 需使用 `XSender` 替代 `EditorSender` 进行开发

#### 问题五：视图组件为空

- `LoginView.vue` 和 `ChatView.vue` 均为空壳，需要完整实现

## 六、关键实现细节

### 6.1 SSE 流式消息处理流程

```
用户输入消息
  ↓
1. 立即在 messages 数组追加 { role: 'user', content }
  ↓
2. 追加 { role: 'assistant', content: '', loading: true }
  ↓
3. 调用 postStream('/chat/stream', { userId, sessionId, message })
   - 返回 AbortController 存入 streamController
   - 解析 SSE 事件流：
     event: delta → data = JSON.parse(line) → messages[末尾].content += data.content
     event: done  → data = JSON.parse(line) → 更新 sessionId, messages[末尾].loading = false
     event: error → data = JSON.parse(line) → 显示错误提示
  ↓
4. BubbleList 自动滚动到最新消息（autoScroll）
```

### 6.2 会话切换与历史加载

```
用户点击左侧会话
  ↓
1. currentSessionId = 新 sessionId
  ↓
2. GET /api/chat/history?sessionId=xxx
  ↓
3. 将返回的 [{role, content}] 映射到 messages 数组
  ↓
4. BubbleList 渲染历史消息
```

### 6.3 Conversations 组件数据映射

## 九、待确认问题

1. **Vite 代理 rewrite 规则**：当前配置会去掉 `/api` 前缀，但 API 文档中后端接口路径本身包含 `/api`（如 `/api/chat/stream`）。需要确认后端实际接收的路径是什么，可能需要去掉 `rewrite` 配置。

2. **SSE 请求的 Content-Type**：`postStream` 当前使用 `fetch` API 发送 JSON，需确认后端是否需要额外的 `Accept: text/event-stream` 头。

4. **x-markdown-vue 的 API**：需要安装后确认其 props 和用法，文档地址：https://www.npmjs.com/package/x-markdown-vue

5. **用户清除缓存后的恢复流程**：设计文档提到"清除缓存后凭相同 userId 仍可登录"，需要确认后端是否有接口可以验证一个 userId 是否存在。
